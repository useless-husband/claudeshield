# ClaudeShield 導讀

這份文件寫給第一次看這個專案的人，也讓你在面試時講得清楚它在做什麼、為什麼這樣做。

## 它解決什麼問題

用 Claude Code 這類 AI 助手處理工作檔案時，檔案內容會被送到 Anthropic 的伺服器。如果檔案裡有客戶的身分證字號、電話、合約金額，這些資料就離開了你的電腦。

很多人以為「網路有加密就安全」。但加密只防得了路上被偷看，防不了以下幾件事：

1. 資料本來就是要送給對方的，對方會保存一段時間
2. 有人偷偷把連線改送到別的伺服器
3. 你自己硬碟上的對話紀錄沒有加密
4. Claude 執行的指令把檔案上傳到別的地方
5. 外掛被更新後，偷偷多了一個能看到你對話的東西

ClaudeShield 一次處理這五件事。

## 七個關鍵概念（每個都配一個生活比喻）

### 1. 代號遮罩：像寄信時把收件人換成編號

Claude 讀檔案之前，ClaudeShield 會先把「王小明、0912-345-678」換成「⟦NAME_001⟧、⟦PHONE_001⟧」。Claude 看得懂這是「某個人的名字」、「某支電話」，所以照樣能幫你整理資料，只是不知道實際是誰。

就像公司把文件交給外包翻譯社之前，先把客戶名字換成「客戶 A」「客戶 B」。

### 2. 寫回來時換回真實內容：只有你手上有對照表

Claude 要寫檔案時，寫的是「⟦PHONE_001⟧」。ClaudeShield 在檔案真正寫進硬碟之前，查對照表換回「0912-345-678」。所以你拿到的檔案是完整的，Claude 卻從來沒看過真實資料。

對照表就像那份「客戶 A = 王小明」的名單，只鎖在你自己的抽屜裡。

### 3. 同一個值永遠是同一個代號：讓 Claude 還能做比對

如果王小明出現在兩份文件裡，兩邊都是 ⟦NAME_001⟧。這樣 Claude 才知道「這兩份講的是同一個客戶」。

而且一個名字只要被遮過一次，之後它單獨出現（例如檔名「王小明_合約.txt」）也會被遮。這是用 Aho–Corasick 演算法做的：它像一個同時記住幾千個關鍵字的掃描器，只要從頭到尾掃一次，就能找出所有關鍵字。

### 4. hooks：Claude Code 在每個關鍵時刻都會「打電話問你」

Claude Code 提供了 hooks 機制，在幾個時間點會先執行你指定的程式：

- 開始工作階段時（SessionStart）
- 你送出訊息時（UserPromptSubmit）
- Claude 要用工具之前（PreToolUse）
- 工具用完、結果送給 Claude 之前（PostToolUse）
- 回覆顯示在螢幕上時（MessageDisplay）

ClaudeShield 就是在這些時間點插手：檢查、遮罩、還原、擋下。比喻：像大樓的警衛，每個人進出都要經過他。

### 5. 啟動前檢查：出門前檢查門鎖和瓦斯

每次開始前，ClaudeShield 會檢查：

- 有沒有被設定代理伺服器、或被改道到別的伺服器
- Anthropic 的加密憑證是不是正版
- IP 是不是 Anthropic 官方網段
- 電腦裡有沒有被偷裝可以解開加密連線的根憑證

「憑證釘選」是其中的重點。一般程式相信系統裡所有的根憑證，但如果有人在你電腦裡多裝一個，就能假冒任何網站。ClaudeShield 只相信它自己內建的那 5 張，所以別人多裝的不會被採信。比喻：一般人看到制服就相信是警察；ClaudeShield 只認得自己背下來的那幾張證件號碼。

### 6. 加密保險箱：日記本鎖進保險箱

Claude Code 會把對話紀錄存在硬碟上，而且沒加密。ClaudeShield 用 macOS 內建的 `hdiutil` 建一個 AES-256 加密的磁碟映像，把對話紀錄搬進去，原本的位置留一個「捷徑」。

最巧妙的地方是：保險箱關著時，捷徑指向的位置不存在，而且一般程式沒有權限在那裡建立資料夾（`/Volumes` 只有系統管理員能寫）。所以 Claude Code 寫不出任何沒加密的紀錄，等於「保險箱沒開，日記就寫不了」，而不是「寫在桌上」。

### 7. 對外連線判斷：分清楚「拿東西進來」和「送東西出去」

`curl https://網站` 是下載，`curl -d @客戶.csv https://網站` 是上傳。ClaudeShield 有一個小型的 shell 解析器，看懂指令裡的引號、變數、管線，判斷：

- 會連到哪裡
- 是在下載，還是在送資料出去

送資料到不在白名單的地方就擋下或詢問。比喻：海關不攔進口的觀光客，但會檢查要帶出國的行李。

在敏感資料夾裡，還會再開 Claude Code 內建的「沙盒」，由作業系統直接限制指令能連到哪裡，等於多一道實體的門。

## 一個真實踩到的難題（面試很好講）

指令執行**失敗**時，Claude Code 走的是另一條路（PostToolUseFailure），而那條路**不能改寫輸出**。如果一個程式印出客戶身分證後當掉，那段文字就會原封不動送給 Claude。

我試了四種方法：

1. 叫它停下來（`continue: false`）：實測無效，Claude 照樣看到了。
2. 用 `trap` 包住指令，讓失敗也變成成功：Claude Code 直接拒絕執行含 `trap` 的指令。
3. 改用 `{ }` 和 `$?`：Claude Code 的權限檢查「看不懂」這種寫法，每次都要人工核准，太難用。
4. **最後的解法**：只在「沙盒本來就會自動放行所有指令」的資料夾裡包裝指令，並回答「允許」。因為沙盒原本就會自動放行，所以這個「允許」沒有給出任何新的權限；而系統層級的限制都還在。

這個過程的重點是：**每一步都是實際跑 Claude Code 驗證的，不是只看文件猜的。**驗證用的小程式放在 `scripts/probes/`。

## 面試可能會問的 10 個問題

**1. 為什麼不直接用 HTTPS 就好？**
HTTPS 只保護傳輸途中。資料到了對方伺服器還是會被處理和保存；你硬碟上的紀錄也沒加密。ClaudeShield 處理的是「根本不要送出去」和「存在本機也要加密」。

**2. 遮罩之後 Claude 還能正常工作嗎？**
大部分可以。代號保留了類型（姓名、電話、金額），同一個值永遠同一個代號，所以整理、比對、改寫都沒問題。需要計算金額時，Claude 會寫程式在本機算，程式讀到的是真實數字。

**3. 怎麼保證 Claude 真的沒看到真實資料？**
`scripts/e2e.sh` 用真正的 Claude Code 跑：檢查 Claude 的回答、存下來的對話紀錄都沒有真實值，而它寫出來的檔案有。這是端對端驗證，不是只測自己的函式。

**4. 多個 hook 同時寫對照表，不會打架嗎？**
用 `flock` 檔案鎖，一次只有一個程式能改；寫入時先寫暫存檔再改名，所以不會出現寫到一半的檔案。有一個測試是開 6 個程式同時寫，檢查 180 筆全部都在、代號沒有重複。

**5. 為什麼用規則（正規表示式）而不是 AI 模型來偵測？**
每次 Claude 用工具都要跑一次，必須在幾毫秒內完成。AI 模型要幾百毫秒，還要很大的檔案。規則加上檢查碼（例如身分證最後一碼）可以很準、很快；規則抓不到的名字，讓使用者自己列在 terms。

**6. 身分證檢查碼怎麼算？**
第一個英文字母換成兩位數，十位數乘 1、個位數乘 9，後面八個數字依序乘 8、7、6…1，再加上最後一碼，總和要能被 10 整除。這能排除大部分「長得像但不是」的字串。

**7. 憑證釘選是什麼？為什麼重要？**
一般程式相信系統裡所有的根憑證。如果有人在你電腦裡多裝一張（公司管理的電腦、某些防毒軟體會這樣做），就能解開你所有的加密連線。ClaudeShield 只用內建的 5 張根憑證驗證 Anthropic，所以多裝的那張不會被採信。

**8. 效能怎麼優化的？**
用效能分析工具（pprof）發現正規表示式引擎吃掉大部分時間。做了兩件事：先用簡單的字串比對篩掉不可能命中的行；對「已知值」改用 Aho–Corasick 一次比對。全面偵測從 97 毫秒降到 11 毫秒，大型 CSV 從 227 毫秒降到 78 毫秒。

**9. 這個工具有什麼做不到的？**
散文裡沒有線索的名字抓不到；圖片和 PDF 不會遮罩，只會擋下；程式算出來的總額如果直接印出來，Claude 看得到；它改變不了 Anthropic 保存資料的政策。README 的「限制」一節全部列出來了。

**10. 出錯的時候是放行還是擋下？**
看位置。在敏感資料夾裡「擋下」（fail closed），因為那裡的資料最重要；在一般資料夾「放行並顯示警告」（fail open），避免一個 bug 讓電腦上所有 Claude Code 視窗都不能用。這是刻意的取捨。
